# Bad Game Pickleball Courts

A responsive web app for organizer-run open play. Players request a place from a shared link; organizers approve requests, manage the daily roster, configure each court, and record match results. The app uses Firebase Hosting, Authentication, and Cloud Firestore. It does not use SQLite.

## What it does

- Daily session with an adjustable player limit (32 by default). Approved reservations hold spots before check-in. Later approvals go to a waitlist; a removed or checked-out reservation promotes the oldest waitlisted player.
- Public signup for an existing player profile or a new profile with name, skill level, division eligibility, and optional photo. All public requests require organizer approval. Existing-profile claims are also reviewed.
- Organizer check-in, check-out, rejection, removal, directory search, profile editing, and daily reset. Reset preserves player profiles and past results and creates a new signup link.
- Reusable courts with separate skill eligibility, open/mixed/women/men divisions, and singles/doubles format. Each court can draw and start independently. One player cannot be on two active courts.
- Winner recording adds one win to each winner and one loss to each opponent. Results can be saved only once. The dashboard shows player records and recent results.

## Firebase setup

The web config for project `bad-game-pickleball` is in `src/firebaseConfig.js`. This config identifies the Firebase web app and is intended to be public. **Keep service account JSON files private; never put one in `public/`, `src/`, Git, or Hosting.** The repository ignores common service account filenames.

In [Firebase Console](https://console.firebase.google.com/project/bad-game-pickleball/overview):

1. Create the **Cloud Firestore** database if it is not already created. Choose a location near your players. The rules in this repository replace temporary setup rules at deployment.
2. Under **Authentication → Sign-in method**, enable **Anonymous** for player signups. Enable either **Google** or **Email/Password** for organizers. Add your Hosting domain to authorized domains if Firebase asks for it.
3. Create the first organizer's Authentication account. For Google sign-in, signing in once from `/admin` creates the Auth user, even though access is refused until the next step. For email/password, create the user in Firebase Console.
4. In Authentication → Users, copy that user's **UID**. In Firestore, create `organizers/{UID}` with an `active` boolean field set to `true`. Only a project administrator or the Admin SDK can create this document; web clients cannot grant themselves organizer access.
5. If using the Admin SDK instead of the Console for step 4, set `GOOGLE_APPLICATION_CREDENTIALS` to the private service account file on your machine and run `npm run bootstrap:organizer -- organizer@example.com`. The account must already exist in Firebase Authentication.

Photos are compressed to small JPEGs and stored in Firestore with the profile. This avoids requiring Cloud Storage billing for this first version. Approve only real people: the public link is shared with the group, and anonymous accounts can still submit pending requests until the organizer reviews them.

## Run locally

Requires Node.js 20 or newer. The Firestore emulator also requires Java 21 or newer.

```powershell
npm install
npm run dev
```

Open `http://localhost:5000/admin` for the organizer dashboard. The web app automatically uses the local Auth and Firestore emulators at that address. Emulator data is temporary unless you export it. The signup page needs the session link generated by the dashboard.

Run the domain tests with `npm test`. To run the Firestore rules and full signup/court flow tests, use:

```powershell
npx firebase emulators:exec --only auth,firestore --project bad-game-pickleball 'node --test tests/app-integration.test.js tests/firebase-rules.test.js'
```

## Deploy

Sign in to Firebase CLI with a Google account that can manage project `bad-game-pickleball`, then run:

```powershell
npm install
npm run deploy
```

This builds the two web pages and deploys Hosting plus Firestore rules and indexes. The expected Hosting address is `https://bad-game-pickleball.web.app`; Firebase confirms the address after a successful deploy. Share the exact signup link shown in the organizer dashboard for each daily session.

The current signed-in CLI account must have project access. A Firebase web config or private service account file alone does not grant Hosting deployment permission.
